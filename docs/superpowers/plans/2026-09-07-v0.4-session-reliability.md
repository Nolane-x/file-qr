# File QR v0.4 Session Reliability Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn each File QR code into a reusable ten-minute lease with sequential receiver attempts, interrupted-transfer resume, ICE recovery, and an optional server-side TURN credential boundary.

**Architecture:** Separate the durable rendezvous lease from per-receiver transfer attempts. Keep one sender websocket for the full 600,000 ms lease; create a fresh peer/data-channel per receiver attempt; persist compatible partial files locally and resume from a byte offset. Direct WebRTC remains primary, one ICE restart is allowed per attempt, and TURN is optional server-side infrastructure.

**Tech Stack:** JavaScript ES modules, Node test runner, Cloudflare Workers + Durable Objects, WebRTC RTCDataChannel, OPFS, Tauri 2 shared web runtime.

**Spec:** `docs/superpowers/specs/2026-09-07-v0.4-session-reliability-design.md`

## Global Constraints
- Session lifetime is exactly `600_000` ms from creation.
- The same code supports sequential receiver attempts for the entire lease.
- Only one receiver is active at a time.
- No new receiver is admitted at/after expiry.
- An attempt admitted before expiry may finish after expiry.
- Signaling stores no file bytes.
- Sender file remains local until a data channel opens.
- TURN long-lived credentials never enter browser code or checked-in source.
- v0.4 does not change optical FQR1 or introduce LAN discovery.
