# File QR v0.2 Reliability + Scanner Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship File QR v0.2 with web QR scanning on Android/Windows, paste convenience, wake-lock protection, ETA/connection diagnostics, redundant STUN configuration, and the shorter `fileqr.nolane-file.workers.dev` production hostname.

**Architecture:** Keep `main.js` as orchestration while extracting pure/isolated helpers for receive payload parsing, scanner camera lifecycle, wake lock, and progress/ETA. Keep WebRTC direct-P2P semantics; expose an `iceServers` injection boundary for future TURN credentials without enabling TURN in this milestone.

**Tech Stack:** JavaScript ES modules, Node 24 test runner, Vite 8, `qr@0.7.0`, WebRTC, Cloudflare Workers Static Assets, Tauri 2.

**Spec:** `docs/superpowers/specs/2026-09-06-v0.2-reliability-scanner-design.md`

## Global Constraints

- Rendezvous TTL remains exactly `600000` ms.
- File bytes never enter the signaling service.
- Optical `FQR1` multi-frame scanning remains native-only.
- Scanner may parse receive codes/URLs but must never navigate scanned URLs.
- TURN long-lived secrets must never enter browser/Vite variables.
- No manual transport selector, account, dashboard, history, chat, LAN discovery, optical FEC, signing, or auto-update in v0.2.
- Supported preview remains Windows + Android.
