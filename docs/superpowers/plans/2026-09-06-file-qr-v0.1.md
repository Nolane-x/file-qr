# File QR v0.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the first working File QR foundation with a polished WebRTC web client, 10-minute ephemeral signaling, and a Tauri Windows/Android shell that adds repeatable offline QR-frame streaming.

**Architecture:** Shared dependency-light JavaScript protocol modules define receive codes, chunk envelopes, CRC32 and optical frames. The web client uses WebRTC for file bytes and a Cloudflare Durable Object only for ephemeral SDP/ICE signaling. Tauri 2 wraps a sibling UI that can use the same network protocol plus camera/screen optical transfer.

**Tech Stack:** JavaScript ES modules, Vite 8.2.2, `qr` 0.7.0, WebRTC RTCDataChannel, OPFS, Cloudflare Workers/Durable Objects, Wrangler 4.129.0, Tauri CLI 2.11.4/API 2.11.1, Rust stable in CI, GitHub Actions/Pages.

**Spec:** `docs/superpowers/specs/2026-09-06-file-qr-v0.1-design.md`

## Global Constraints
- Windows and Android only.
- Rendezvous TTL is exactly 600 seconds.
- File bytes never transit the signaling service.
- Web primary transport is WebRTC.
- Native adds offline QR streaming; optical v0.1 uses repeated versioned frames with CRC32, not an unverified fountain-code claim.
- A session supports one sender and one receiver.
- No account, history, cloud drive, chat, iOS, macOS, or Linux scope in v0.1.
